## 1. 目的

50人規模製造業(アルファメック)の社長個人業務を対象に、AIで以下を実現する:

- **スリム化**: 定型業務(メールチェック、月次集計、文書下書き)をAIに移管
- **効率化**: 情報の検索・要約・突合を数分で完了させる
- **拡張**: 一人では処理しきれなかった情報量(全商談・全カイゼン・全査定材料)を判断に組み込む
- **インプット増**: 記憶頼みだった定性情報(口頭・電話・訪問)を構造化して蓄積
- **論理的判断**: 経営判断(人事・設備投資・査定)を、根拠データと判断記録を伴う形にする

## 3. 入力の3系統(ユーザー定義)

1. **商談情報**: 媒体あり(メール・FAX・見積書・売上データ・生産管理データ・営業記録)+媒体なし(電話・訪問・来訪の記憶)
2. **従業員査定情報**: 定量(LINE WORKS・カイゼン提出・目標管理シート・作業履歴・勤怠・有給・資格)+定性(口頭・評判・出来事・問題)
3. **経理情報**: ISO9001月次入力(残業・売上・月次報告書・買掛)

出力: 年1回ISO9001マネジメントレビュー(方針策定→目標管理シート→力量表更新)+随時の経営判断(人事・設備投資・査定)

**国内事例に共通する成功パターン(5点)**

1. 社長(または経営ファミリーの1人)が自らAIを触る。委任・ベンダー丸投げの成功例はほぼない
2. 「AI導入」でなく「困りごと」から小さく始め、数週間で1つ効果を出して横展開
3. AIの前に「社長の頭の中と社内データの言語化・一元化」(判断基準・議事録・カイゼン事例・日報を貯める仕組みが先)
4. 「社長の分身」は理念+判断基準+FAQで作り、まず社員の壁打ち相手から。①社員の質問対応→②提案の壁打ち→③社長自身の意思決定補助、の順に信頼を積む。最終判断は必ず人間
5. AIに前工程(収集・要約・ドラフト)の50〜80%を任せ、人は判断と実行に集中する仕事の再設計

## 6. 貴社プランへの脚色提案

リサーチ結果を6領域構想に重ねたとき、追加・修正すべき点は次の7つ。

### 提案A: 7つ目の領域として「分身(マンデーくん)」を新設する【最重要】

旭鉄工「AIキムテツ」・ノジマ「Bunshin」・THA「AI社長」に共通する最大の発見は、**6領域のどれでもない「社長の判断基準そのものをAI化する」領域**が国内で最も成果を出していること。貴社には既に素材がある:

- 朝礼原稿(Notionに蓄積済み: 力量表について、ISO9001対応について等)
- 給与査定シートの評価コメント(=査定の判断基準の言語化)
- 商談アーカイブの対応記録(=顧客対応の判断基準)
- ISO審査での受け答え記録

これらを「判断基準集」として1ファイルに編纂し、**マンデーくん=野村社長の分身AI**として育てる。リポジトリ名 monday-kun をこの分身の名前としてそのまま使う。運用は国内事例の3段階を踏襲:
①社員からの質問対応(「社長ならどう言うか」)→ ②社員の提案の壁打ち相手 → ③社長自身の意思決定補助

### 提案B: 「記憶頼み」の入り口を音声で塞ぐ(商談領域)

貴社の入力①の弱点は「電話・訪問・来訪など記憶に残っているもの」。Granola型+営業日報AIの型を適用:

- 顧客訪問・電話直後にスマホで1〜2分の音声メモ(または要点の走り書き)
- AIが「会社名｜ステータス｜日付」の既存フォーマットに正規化して商談アーカイブへ下書き
- 保存先は決定済みの役割分担どおり「Google Drive=一次受け(生メモ)、Notion=正規化後サマリ」
- 週次でAIが全商談を横断し「クレーム兆候・納期不満・引き合い変化」レポート(VOC分析)

### 提案C: 年1回の重いレビューを「月次15分ミニレビュー」に分割(製造・経理領域)

ISO9001の月次入力は既にある。これを9.3.2のインプット項目別にAIが毎月整理・傾向分析し、マネジメントレビュー資料ドラフトを自動生成。年1回のレビューは「12枚の月次ドラフトの承認と方針化」に変わり、審査対応と実効性が両立する。力量表は半期ごとにAIが「単能工リスク(その人しかできない工程)」を抽出し「資源の妥当性」インプットへ接続。

### 提案D: 査定は「AI点数化」ではなく「AI事実収集」に徹する(査定情報②)

海外・国内・法務の3方向すべてが同じ結論。AIの役割は:

- LINE WORKS・カイゼン提出・作業履歴・勤怠・資格から「この半期の本人の事実リスト」を査定面談前に自動生成
- 定性情報(出来事・問題)は社長が随時音声メモ→AIがタグ付けして人別に蓄積
- 点数化・順位付けはしない。評価コメントの下書きと事実の突合まで
- 9-4の5原則(最終判断は人間、仮名化、透明性、バイアス監査、不服申立て)を制度に明記

### 提案E: 経営判断に「型」を入れる(企画領域の中核化)

判断の論理化はツールでなく型で実現する。導入順:

1. **毎朝30分のAI壁打ち**(投資ゼロ、国内事例で売上30%増の報告)を秘書ブリーフィング直後に習慣化
2. **1-way/2-way door仕分け表**を作り、2-way(工程変更・販促・ツール導入)は部門長へ委譲して社長の決裁件数自体を減らす
3. **1-way案件(500万円超・長期契約・人員)には必須3点セット**: AIプレモーテム1枚+AI反対役(銀行員・主要顧客・工場長・後継者ペルソナ)との問答ログ+ディシジョンジャーナル記録
4. **重要仮説5〜10個の月次ベイズ更新**(「A社の来期発注は維持されるか: 70%」)をリスク・機会管理に接続

### 提案F: 秘書は「固定セクションのダイジェスト契約」で設計する

Doney Li型の契約をそのまま採用: AIが自律的に動いてよいのは「処理済み(Handled)」枠のみ。毎朝のブリーフは「要対応(3〜5件)/本日の予定/参考情報/処理済み/会議準備」の固定5セクション+業界ニュース4カテゴリ(顧客業界・材料相場・競合技術・補助金規制)。既存の日次ブリーフィングページを、この形式に改める。

### 提案G: 順番の原則 —「データの居場所づくり」が全領域の前工程

高瀬金型・オプトサイエンスの教訓。ウェブ領域・MAP連携などの拡張は、商談・査定・経理の3系統が「AIが読める場所」に集まってから。逆に言えば、散在データの一元化自体が最初の成果物になる。また Dan Shipper と中小企業白書の一致点として、**この仕組みは社長自身が毎週操作し続けること**が全社展開の前提条件。情シス担当や外部への委任では停滞する。

## 9. ガバナンス(監査領域の具体化)

### 9-1. 拠り所とする公的基準

- **個人情報保護委員会の生成AI注意喚起(2023-06-02)**: 従業員・顧客の個人データをAIに入力するのは「利用目的の範囲内」かつ「AI事業者が入力データを機械学習に使わないことを確認済み(学習オフの法人契約)」の場合のみ。氏名は社員番号等に置換して入力する。
  https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert/
- **AI事業者ガイドライン(総務省・経産省)**: AI利用者に「利用ルール整備・従業員教育・出力の人間による最終確認」を要求。社内ルールは「技術/法務/組織運用」の3領域で構成するのが定石。
  https://www.ipa.go.jp/disc/committee/expert-group-on-aigfb.html

### 9-2. アルファメックAI利用ルール(A4 2〜3枚で策定する)

既存の「個人用AI使用原則」(Notion AI作業ハブ)を組織版に昇格させ、以下4点に絞る:

1. 許可ツール一覧(法人契約・学習オフ確認済みのもののみ。無料個人アカウントの業務利用は禁止)
2. 入力禁止情報(顧客図面・個人情報・原価・パスワード。人事情報は仮名化必須)
3. AI出力は必ず人間が確認してから使用(「AIは下書き・分類・集計まで。社外送信・データ削除・人事記録の書き込みは必ず人間が実行」)
4. 相談窓口1名の指名と、朝礼+年1回の教育

### 9-3. AIエージェントの暴走対策(Human-in-the-loop設計)

- 権限の最小化: エージェントには承認済みツール・最小限のデータアクセスのみ与える
- 決定境界の明文化: 定型処理は自動可、「金額基準超・社外送信・削除・人事記録変更」は人間承認ゲート必須
- 全アクションのログ保存(監査領域の実行ログDBに集約)
- 参考: https://wandb.ai/site/articles/guardrails-for-ai-agents/

### 9-4. 査定・人事へのAI適用 5原則

1. **最終判断は必ず人間**: AIは事実収集と下書きまで。AI出力そのままの評価は人事権濫用と判断されるリスク
2. **個人データ入力条件の遵守**: 上記PPC注意喚起の通り。仮名化+学習オフ法人契約
3. **透明性**: AIをどの工程で使うか従業員に事前説明し、評価根拠を本人に説明できる状態を保つ
4. **バイアスの定期監査**: 「日報を書くのが上手い人が有利」等の偏り増幅を評価分布で定期チェック
5. **不服申立て経路**: AI関与評価への異議窓口と人間のみでの再評価プロセスを事前に用意。導入初期は賞与・昇格への反映を限定
